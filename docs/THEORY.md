# WhichOne: теория перед практикой

Клиент отправляет запрос. Controller читает DTO и запускает validation. Service проверяет пользователя и принадлежность квиза, выполняет расчёт. Repository обращается к БД. Entity описывает таблицу; она не выдаётся непосредственно клиенту.

Регистрация превращает пароль в BCrypt хеш. Хеш не расшифровывают: PasswordEncoder.matches сравнивает пароль входа с сохранённым хешем. JWT содержит username, issuer, audience и время действия; подпись проверяет Spring Security. JWT не шифрует содержимое и не содержит пароль.

Автор берётся из проверенного токена. Присланный authorId или role не принимается. Разрешение запроса и принадлежность объекта — две отдельные проверки: быть вошедшим пользователем недостаточно для изменения чужого квиза.

DTO чтения варианта содержит только id и text. correct, outcomeCode и weight нужны авторскому определению, но не выдаются при получении квиза.

Обучающий результат: за правильный выбор добавляются points вопроса. Например, правильный вопрос на3 балла и неправильный на2 дают3/5 =60%.

Личностный результат: веса выбранных вариантов складываются по outcomeCode. При одинаковой сумме выигрывает первый исход в outcomes. Это заранее заданное правило, а не случайность и не алфавитная сортировка.

Опубликованный квиз неизменяем: правильные ответы и исходы старых попыток не могут незаметно изменить смысл. Черновик можно заменить целиком; его дочерние ID при этом меняются.

@Transactional объединяет проверку, расчёт и сохранение попытки: некорректный вариант не оставляет частично сохранённого результата. Flyway выполняет V1 схемы один раз; hibernate.ddl-auto=validate проверяет соответствие сущностей схеме.

Статистика использует сохранённые попытки текущего пользователя. Среднее — среднее процентов учебных попыток с одинаковым весом каждой попытки. При отсутствии учебных попыток среднее равно null: данных ещё нет.
